STARS — Server Provisioning Request

Internal marketing-analytics web tool · lightweight Python (Streamlit) app · hosted on a Windows server

1 · Machine & specs

Operating systemExisting Windows server (Windows Server 2019/2022, or Windows 10/11 Pro). Can run on a shared box with spare capacity.
CPU2 vCPU
RAM4 GB available to the app
Free disk~10 GB free (the app + Python + dependencies; no database server needed)

2 · Software to install

  • Python 3.11 (from python.org — tick “Add to PATH”)
  • Git for Windows
  • NSSM (to run the app as a Windows service — nssm.cc)
  • OpenSSH Server (built-in Windows feature — enables automated deployments)

3 · Network / firewall

InboundOpen TCP 443 (HTTPS) for users — or 8501 if access stays internal only.
Inbound (deploy)TCP 22 (OpenSSH) — can be restricted to GitHub Actions / our IPs.
Outbound (required)Allow outbound HTTPS (443) to the internet — specifically:
generativelanguage.googleapis.com
analyticsdata.googleapis.com
api.github.com
⚠ Most important: the app makes outbound calls to the three domains above. If the server’s firewall blocks outbound internet by default, the app installs fine but will not function. Please confirm outbound HTTPS to those hosts is permitted.

4 · Access & domain

Login accountA Windows admin account we can use, with OpenSSH access. We will provide an SSH public key for you to add.
Domain (optional)A subdomain such as stars.orientbell.com with a DNS record pointing to this server, so the tool has a clean HTTPS URL. If internal-only, http://SERVER-IP:8501 is acceptable to start.
HTTPS (if domain)Standard IIS + Application Request Routing reverse proxy to 127.0.0.1:8501 with an internal certificate.

5 · Please send back

  • Server IP / hostname
  • SSH username (we’ll supply the public key to authorise)
  • Confirmation that inbound 443 (or 8501) and outbound 443 to the three domains are open
  • The subdomain, once created (if applicable)

What it does NOT need

  • No database server
  • No inbound access to internal systems
  • No GPU / heavy compute (AI runs on Google’s cloud, off-server)

Data & security

  • App data (small text files) syncs to our private GitHub repo
  • API keys stored in a local, restricted config file only
  • Access protected by a shared team password
